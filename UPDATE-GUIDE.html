Samaksh Travels — Safe Update Guide

How to add new features later without breaking the live site and without wasting tokens · Site: https://samakshtravels.com

1. The short answer

Work on a separate copy (a "branch"), check it, then publish only when happy. Ask for one feature at a time, and give Claude the two project files so it never has to re-read the whole site. Your live site stays untouched until you say "publish".

2. What you already have

  • Project folder: Documents/samaksh-travels on your computer.
  • Backup + history: github.com/Samakshmahajan04/samaksh-travels — every change is saved; any change can be undone.
  • Notes for Claude: CLAUDE.md (map of the site) and EDITING-GUIDE.md. Keep these updated.
  • Live site: updates about one minute after a change is "pushed" to the main branch.

3. Step-by-step: adding a new feature

  1. Write the idea first (2 minutes). One short paragraph: what it does, where it appears, what it should look like. Example: "Add a Goa package page with 3 photos and a Book button."
  2. Open Claude Code in the folder Documents/samaksh-travels. Claude reads CLAUDE.md automatically. (Or attach CLAUDE.md and say "read this first".)
  3. Say: "Work on a new branch called feature-name. Don't touch main." A branch is a safe copy. The live site is not affected.
  4. Ask for ONE feature. Name the exact section or file ("in the packages section", "in js/main.js"). Don't say "improve the website".
  5. Preview it locally: ask "start a local preview". Open it and check on laptop and phone size. Give small fix requests ("make the button bigger"), not rewrites.
  6. Test the important things: the enquiry form still sends to your inbox, WhatsApp button works, phone numbers correct, page loads without errors.
  7. Publish: say "merge to main and publish". Wait a minute, hard-refresh the live site (Cmd+Shift+R) and check.
  8. Update the notes: say "update CLAUDE.md with what changed". This keeps the next update cheap.

4. How to protect the existing website

RiskProtection
Whole site changes by accidentAlways use a branch; say "only change X, leave everything else exactly as it is".
A change breaks somethingEverything is saved in GitHub. Say "undo the last change" or "go back to the version from yesterday" and republish.
Form stops sendingNever change CONFIG.email or the form code unless needed; if the email address changes, send a new test enquiry and activate it again.
Google Search stops trusting the siteKeep the google-site-verification tag, CNAME file, robots.txt and sitemap.xml. Don't delete them.
Domain stops workingNever delete the CNAME file or the GoDaddy DNS records.

5. How to use the fewest tokens

  • One change per message and name the file/section. Claude then edits a few lines instead of reading everything.
  • Start with CLAUDE.md — it already says which file holds what.
  • Avoid big open requests like "redesign the site" or "make it better". Ask for a specific result.
  • Batch small fixes into one message (e.g. three wording changes together).
  • Ask for short answers: "keep replies short".
  • Skip 3D re-checks unless you changed 3D files (js/scene.js); screenshots cost tokens.
  • Plan new pages separately: a new page (e.g. goa.html) is cheaper and safer than rewriting index.html.

7. Bigger features (plan before asking)

  • Photo gallery, reviews, blog: new pages or sections; safe and cheap.
  • Online payment, customer login, admin panel: need a backend service and cost money. Decide the provider first, build in a branch, and test with fake payments.
  • Auto WhatsApp flow: needs the paid WhatsApp Business API.
